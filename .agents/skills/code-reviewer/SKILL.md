完整扫描规格符合轴与标准符合轴，输出结构化报告

## 审查原则

- **全量单次扫描**：单次运行完整扫描两个轴线并一次性输出所有问题，不分批提出新问题
- **切片最小改动**：仅核验当前切片代码是否忠实实现关联 Issue 需求，改动保持最小必要

## 双轴审查清单

### 1. 规格符合轴
核对代码实现是否符合需求规格：
- 需求完成度：核对关联 Issue 规定的业务行为与验收场景是否完整实现
- 改动边界：核验未越界修改公共契约与无关文件

### 2. 标准符合轴
核对代码质量与架构规范：
- 领域纯度：业务逻辑与状态机内聚在 domain 层，外部交互通过 ports 接口隔离
- 测试有效性：单元测试与验收测试包含实质断言
- 资源与并发安全：检查潜在的资源泄露与并发阻塞隐患

## 问题分级

- **P0 (阻断)**：需求未实现、私改契约、领域纯度破坏、缺少有效测试。阻断合并
- **P1 (建议)**：代码异味、边缘异常处理欠缺。由作者修复或说明权衡
- **P2 (提示)**：命名与排版微调。不影响合并

## 输出格式

```markdown
# Code Review 报告

## 规格符合轴
- [P0/P1/P2] <问题描述>

## 标准符合轴
- [P0/P1/P2] <file_path>: <问题描述>

## 判定
- 结果: APPROVED / REQUEST_CHANGES (存在 P0 时为 REQUEST_CHANGES)
- P0: <N> | P1: <N> | P2: <N>
```
